# AI_NOTES

## 1. Инструменты и промпты

Использовал Kimi Code CLI, read-only субагентов для независимого ревью и проверки тестовой матрицы, Docker Compose с PostgreSQL, а также официальную документацию Laravel 13.

Ключевой исходный промпт дословно:

> Мне нужно сделать тестовое задание вот ссылка https://github.com/rcsi-science/demo-booking. Мне нужно сделать полностью всё задание. Скопирой это тествое в данную папку.  Давай использовать мультиагентность.
> Для аркестрации используй kimi3.1 high, для других задач используй kimi2.8.
> Сначала нужно сделать план и спецификацию и будем идти по нему.
> Не забывай, что нужно писать тесты дл проверки, используй способ разработки TDD.
> Иди строго по плану, не делай больше, чем просят.
> Перед началом разработки прочитай readme.md
> На компьютере уже установлен docker.

## 2. Ошибка ИИ

Субагент при ревью предположил, что исходный `store` возвращает `200` вместо `201`. Первый красный прогон показал фактический ответ `201`: Laravel 13 сам формирует этот статус для только что созданной модели. Я исправил ожидание тестов на `201` и удалил ложный пункт из `REVIEW.md`.

## 3. Самостоятельная проверка

Не доверил статическому разбору временных зон и гонки. Кроме полного прогона 46 feature-тестов (129 проверок) на PostgreSQL, выполнил `migrate:fresh --seed` и реальные HTTP-запросы.

Отдельно проверил:

- запрос со смещением `+05:30` сохраняется как ожидаемый момент UTC;
- на временном PHP-сервере с четырьмя рабочими процессами два параллельных запроса на один слот вернули `201` и `409`, в базе осталась одна бронь;
- чужой пользователь получил `403`, автор — `204`, после удаления в базе ноль броней;
- Pint и финальный diff не содержат непредусмотренных изменений.

Финальный read-only агент отдельно проверил соответствие контроллера и тестов требованиям README; нарушений он не нашёл.
